अमेझॉनने जगातील सर्वात मोठे क्लाउड प्लॅटफॉर्म बनवण्याचा कधीही इरादा केला नव्हता. आपल्या अभियंत्यांनी दर काही महिन्यांनी एकच पायाभूत सुविधा पुन्हा तयार करण्यापासून रोखण्यासाठी प्रयत्न करताना ते त्यात अडकले.

## आतल्या गोंधळाने सुरुवात केली

२०००च्या आसपास, अमेझॉन Merchant.com बनवत होते — एक उत्पादन जे Target आणि Marks & Spencer सारख्या तृतीय-पक्ष विक्रेत्यांना अमेझॉनच्या पायाभूत सुविधांवर ई-कॉमर्स स्टोअर्स उघडण्यास परवानगी देणार होते [2]. त्यानंतर जे झाले ते संघटनात्मक गोंधळ होता. प्रत्येक टीम स्वतःच्या आवृत्तीचे स्टोरेज, कॉम्प्युट आणि डेटाबेस प्रिमिटिव्ह बनवत होती. कोणते सामायिक API नाहीत, कशाही गोष्टीत प्रवेश करण्याचा कोणताही मानक मार्ग नाही.

मग त्यांनी अमेझॉन जे करते ते केले: त्यांनी एक दस्तऐवज लिहिला. उन्हाळ्यात २००३ मध्ये, Jeff Bezos च्या घरी एक कार्यकारी बैठकीत, नेतृत्व टीमने कंपनीची मुख्य क्षमता ओळखण्यासाठी एक व्यायाम केला. उत्तर होते विश्वसनीय, स्केलेबल, वितरित प्रणाली बनवणे [2]. Andy Jassy — तेव्हा VP, आता Amazon चे CEO — यांनी स्पष्ट पुढचा टप्पा पाहिला. त्यांनी मूळ AWS दृष्टिकोन दस्तऐवज लिहिला, "इंटरनेटसाठी ऑपरेटिंग सिस्टम" म्हणवल्या जाणाऱ्या गोष्टी बनवण्यासाठी **५७ लोकांची** मागणी केली [2].

तो दस्तऐवज AWS बनला.

## पहिल्या सेवा (२००४–२००६)

येथे एक गोष्ट आहे जी बहुतेक लोक चुकीची सांगतात: **SQS ही पहिली सार्वजनिक AWS सेवा होती, S3 किंवा EC2 नाही** [6]. Amazon Simple Queue Service नोव्हेंबर २००४ मध्ये प्रिव्ह्यूमध्ये लाँच झाली — स्टोरेज किंवा कॉम्प्युट सार्वजनिकरित्या अस्तित्वात येण्याआधी एक वर्षाहून अधिक. हे समजते जर तुम्ही विचार केला तर. अमेझॉनला इतर काहीही ऑफर करण्यापूर्वी त्याच्या स्वतःच्या आंतरिक सेवा डिकपल करण्याचा मार्ग आवश्यक होता.

मग आल्या त्या दोन सेवा ज्यांनी खरोखर उद्योग बदलला:

- **Amazon S3** (Simple Storage Service) — मार्च १४, २००६ रोजी लाँच झाले. स्केलवर ऑब्जेक्ट स्टोरेज, फक्त वापरलेल्यासाठी पैसे द्या [3]
- **Amazon EC2** (Elastic Compute Cloud) — प्रिव्ह्यू ऑगस्ट २४, २००६; ऑक्टोबर २००८ मध्ये सामान्यतः उपलब्ध झाले [3]

EC2 आधी, एका स्टार्टअपला भौतिक सर्व्हर विकत घ्यावे किंवा भाड्याने घ्यावे लागत होते, त्यांना प्रोव्हिजन करावे लागत होते, रॅक करावे लागत होते, आणि ट्रॅफिकचे अंदाज चुकीचे नसतील अशी प्रार्थना करावी लागत होती. EC2 नंतर, क्रेडिट कार्ड असलेला एक डेव्हलपर मिनिटांत आवश्यक तितकी कॉम्प्युट मिळवू शकत होता [1]. सॉफ्टवेअर तयार करण्याचे अर्थशास्त्र कायमचे बदलले.

लाँचनंतर तीन वर्षांनी, AWS ची वार्षिक रन रेट $५.८ कोटी होती [3]. आजच्या आकड्यांनी लहान, पण दिशा स्पष्ट होती.

## खरे प्लॅटफॉर्म बनवणे (२००७–२०१२)

AWS ने या वर्षांत "स्वस्त कॉम्प्युट आणि स्टोरेज" ला योग्य क्लाउड प्लॅटफॉर्ममध्ये रूपांतरित करण्यात घालवले. बेपत्ता तुकडे एक-एक करून आले:

- **Amazon CloudFront** (२००८) — जगभर एज डिलिव्हरीसाठी CDN [3]
- **Amazon RDS** (२००९) — व्यवस्थापित रिलेशनल डेटाबेस; कच्च्या EC2 वर MySQL देखभाल संपली [3]
- **Amazon EMR** (२००९) — मागणीनुसार Hadoop क्लस्टर्स, डेटा टीमसाठी [3]
- **Amazon VPC** (२०१०) — Virtual Private Cloud, AWS आत वेगळे नेटवर्किंग [3]
- **Amazon DynamoDB** (२०१२) — स्केलवर NoSQL, अमेझॉनच्या स्वतःच्या शॉपिंग कार्ट आर्किटेक्चरमधून जन्मलेले [4]
- **Amazon Redshift** (२०१२) — पेटाबाइट-स्केल डेटा वेअरहाउसिंग [3]

डेटाबेस सेवा विशेषतः महत्त्वपूर्ण होत्या. RDS आधी, कंपन्या एकतर Oracle ला भरपूर पैसे देत होत्या किंवा कच्च्या EC2 इन्स्टन्सेसवर MySQL स्वतः व्यवस्थापित करत होत्या आणि रात्री २ वाजता काही चुकणार नाही अशी प्रार्थना करत होत्या. AWS ने ती संपूर्ण समस्या आत्मसात केली.

## सर्व्हरलेस बदल (२०१३–२०१६)

AWS re:Invent २०१४ तो क्षण होता जेव्हा उद्योग पुन्हा हलला. **AWS Lambda** लाँच झाले — कल्पना की तुम्हाला सर्व्हरबद्दल अजिबात विचार करण्याची गरज नाही, फक्त एक फंक्शन अपलोड करा आणि प्रति आमंत्रणासाठी पैसे द्या [3]. Lambda ने ते वास्तविक आणि व्यावहारिक बनवण्यापूर्वी सर्व्हरलेस संकल्पना म्हणून अस्तित्वात नव्हते.

त्याच वेळी एंटरप्राइझ अंतराळे भरत होते:

- **Amazon Aurora** (२०१५) — MySQL/PostgreSQL-सुसंगत पण सानुकूल स्टोरेज इंजिनसह, मानक MySQL पेक्षा ५x कामगिरीचा दावा [3]
- **AWS CloudTrail** (२०१३) — ऑडिट लॉगिंग, जे अनुपालन टीमसाठी अनिवार्य ठरले
- **AWS Certificate Manager** (२०१६) — विनामूल्य TLS प्रमाणपत्रे; Symantec बिले संपली

२०१५ मध्ये, AWS अमेझॉनचे **सर्वात फायदेशीर व्यवसाय युनिट** बनले — पहिल्यापासून अमेझॉनला नकाशावर ठेवणाऱ्या किरकोळ ऑपरेशनपेक्षाही अधिक फायदेशीर [4]. हे खरोखरच एक वळण बिंदू होते. आंतरिक गोंधळ कमी करण्यासाठी एक बाजूचा प्रकल्प इतर सर्व गोष्टींना निधी पुरवणारे इंजिन बनला होता.

२०१६ पर्यंत, AWS महसूल **$१२.२ अब्ज** पर्यंत पोहोचला [3].

## प्लॅटफॉर्म परिपक्व होतो (२०१७–२०२२)

या टप्प्यापर्यंत AWS "क्लाउड कॉम्प्युट" असणे बंद झाले होते आणि एंटरप्राइझसाठी जवळजवळ संपूर्ण ऑपरेटिंग वातावरणासारखे काहीतरी बनले होते. मुख्य जोडण्या:

- **Amazon SageMaker** (२०१७) — व्यवस्थापित ML प्लॅटफॉर्म जो प्रशिक्षण पायाभूत सुविधा स्क्रॅचपासून सेट करण्याची गरज काढून टाकतो [5]
- **AWS Fargate** (२०१७) — सर्व्हरलेस कंटेनर; Docker वर्कलोडसाठी Lambda
- **Amazon EKS** (२०१८) — व्यवस्थापित Kubernetes, अभियंते EC2 वर ते चालवत होते हे स्पष्ट झाल्यानंतर
- **AWS Ground Station** (२०१९) — व्यवस्थापित सेवा म्हणून उपग्रह संप्रेषण [3]

रणनीती स्पष्ट झाली: एखाद्या कंपनीला आवश्यक असलेल्या पायाभूत सुविधांचा प्रत्येक तुकडा ओळखा आणि त्याची व्यवस्थापित आवृत्ती बनवा. डेटाबेस, रांगा, स्ट्रीमिंग, व्हिडिओ ट्रान्सकोडिंग, IoT, ML, ब्लॉकचेन, अगदी क्वांटम कॉम्प्युटिंग सिम्युलेशन. २०२० पर्यंत, संख्या **१७५ सेवांपेक्षा** जास्त झाली [3]. ते थांबत नव्हते.

## AI चा जोर (२०२३–आत्तापर्यंत)

जनरेटिव्ह AI लहरीने प्रत्येक क्लाउड प्रदात्याला वेगाने अचंबित केले, पण AWS वेगाने पुढे गेले:

- **Amazon Bedrock** — फाउंडेशन मॉडेल्ससाठी व्यवस्थापित API लेयर: Anthropic चे Claude, Meta चे Llama, Mistral, आणि इतर. मॉडेल पायाभूत सुविधा व्यवस्थापित न करता AI अ‍ॅप्स बनवा [5]
- **Amazon SageMaker AI** (२०२४ पुनर्रचना) — एकीकृत डेटा आणि AI स्टुडिओ म्हणून पुन्हा बांधले, मॉडेल प्रशिक्षण वर्कफ्लो महिन्यांपासून दिवसांपर्यंत कमी केले [5]
- **Amazon Nova** — AWS चे स्वतःचे फाउंडेशन मॉडेल्स कुटुंब, re:Invent २०२४ मध्ये जाहीर [5]

AWS चा AI महसूल रन रेट २०२६ च्या सुरुवातीस **$१५ अब्ज** पार केला [9]. २० वर्षांच्या पायाभूत गुंतवणुकीचा संयुक्त परिणाम या आकड्यांमध्ये स्पष्टपणे दिसत आहे.

Azure ~२३% वर आहे आणि वाढत आहे. Google Cloud ~११% धरतो [8]. AWS आघाडीवर आहे पण अंतर पाच वर्षांपूर्वीपेक्षा कमी आहे — Microsoft च्या OpenAI एकत्रीकरणाने Azure कडे लक्षणीय एंटरप्राइझ वर्कलोड खेचले आहेत, आणि ती स्पर्धा आणखी मनोरंजक होत जाईल.

जे पूर्णपणे आत्मसात करणे कठीण आहे ते म्हणजे मार्ग. सामायिक API तयार करण्यासाठी ५७ लोक मागणी करणारा एक २००३ चा आंतरिक दस्तऐवज बहुतेक देशांच्या GDP पेक्षा अधिक महसूल निर्माण करणारा व्यवसाय बनला. आणि ते तयार करण्याचे मूळ कारण फक्त आंतरिक टीमांना काम दुप्पट करण्यापासून रोखणे होते.
